# 资讯与猪猪伙伴测试用例

适用范围为 HomeSignage 的新闻来源、模型调用、话题筛选与自动发布、设备播报、天气及家庭事项。自动化使用独立的内存 SQLite、模拟设备和测试管理员。浏览器联调用临时端口和独立 Chromium 会话。生产屏幕、正式资讯及家庭事项均不充当测试夹具。

## 运行方法

1. 根目录安装锁定依赖，在 admin 目录安装依赖并运行 npm run build。
2. 根目录执行 npm test 运行全部 Jest 用例。单独验证本功能可执行 npx jest --runInBand --forceExit briefing。Jest 默认不会调用带费用的模型。
3. 浏览器脚本的 playwright-core 已列入项目开发依赖。CHROME_PATH 指向本机 Chrome 或 Edge 可执行文件，或运行 npx playwright-core install chromium。根目录运行 npm run test:browser；全系统用例、实测范围和其他复跑命令见[系统回归测试](系统回归测试.md)。
4. 脚本追加 --live 使用真实中国新闻网 RSS 和本机 GLM_API_KEY，追加 --live --zaobao 使用联合早报官方新闻索引和 GLM。每次选择一条近期标题作为精确关注词，核对真实服务用量、事件和页面。可设置 BRIEFING_SCREENSHOT 保存测试画面；不要保存含密钥的设备启动 URL。
5. 发布后在 /api/docs 浏览 Swagger，在 /admin/briefing 检查供应商就绪状态、采集结果与今日用量。在局域网设备上使用管理后台提供的显示链接。

## 单元用例

| 编号 | 输入及步骤 | 应观察到的结果 |
| --- | --- | --- |
| U01 | 用同一公告分别设置可信 RSS、普通 RSS、Brave、榜单，匹配地区与关注词 | 符合关注词或重大事件规则的近期新闻可触发提醒；未定向时遵守各设备的新闻开关。榜单只更新卡片 |
| U02 | 设置不同城市、未命中关注词、全局屏蔽词和来源屏蔽词 | 被过滤的条目不进入生成流程，检查命中原因 |
| U03 | 分别传入缺发布时间、25 小时前、未来和当前的消息 | 缺日期的资讯按采集时间显示但不主动提醒，旧闻和超出五分钟容差的未来新闻被跳过，近期新闻自动显示 |
| U04 | 免打扰设为 22:00 至 07:00，依次输入 22:00、23:59、00:00、06:59、07:00 和中午 | 起点包含，终点排除；起止相等表示关闭免打扰 |
| U05 | 同一 UTC 时刻转换到上海与纽约，检查日期和工作日 | 分别按设备当地日期和星期判断 |
| U06 | 输入时区拼写错误、非法时间、负间隔、非法温差、空白市名和越界音量 | 拒绝保存；已有组件设置继续有效 |
| U06a | 只填“深圳市”，换成不存在的城市或查询服务超时，再改回“深圳” | 市名即可保存；失败不覆盖旧设置；有无“市”后缀共用晨间记录；换到另一市后旧提醒不可领取 |
| U07 | 输入不支持的模型商、非法模型名、负预算和小数预算 | 返回校验错误 |
| U08 | 输入私网、回环、IPv6 映射回环、链路本地、多播、非法 IP 以及公网 IP | 只放行公网单播；每次 HTTP 跳转重新校验地址 |
| U09 | 解析含 GUID、CDATA、相对原文链接和缺日期的 RSS | GUID 稳定、正文纯文本、原文地址正确、未知时间保持缺失 |
| U10 | Atom 同时提供 self 与 alternate 链接，另有 javascript 链接 | 选择阅读地址，忽略危险链接；含实体声明或非法 XML 时返回明确错误 |
| U11 | 模型返回无效 JSON、编造数字、部分字段有依据、合法来源句编号 | 只采用可定位到原文的句子；不合格台词回退到有依据的文本 |
| U12 | 模拟上游 401、Brave 新闻响应和缺失密钥 | 前者只暴露状态/业务错误码；Brave 请求携带对应鉴权、新鲜度参数和查询词 |
| U13 | 解析早报索引的 news:title、publication_date、loc，混入同路径跟踪链接、站外域名和无效日期 | 保留官网标题及链接，东八区时间换算正确，按最新时间排序，按规范路径去重 |
| U14 | 选择中港台、国际、财经、新加坡各栏；返回 HTTP 304、HTML 或超出预期的 XML | 按栏目选取，304 沿用缓存；页面结构异常可诊断。固定上游，配置无法替换请求主机 |
| U15 | 设备已解锁、未解锁、关闭声音、语音引擎报错 | 仅允许时调用中文朗读；其他情形都显示字幕并回传 subtitle，实际朗读结束回传 spoken |
| U16 | 领取尚未返回时卸载场景，或播放过程中撤回事件 | 迟到任务不开始播放；已开始的语音立即取消，回传 interrupted |
| U17 | 紧急插播、定时提醒、隐藏页面、非当前场景并存 | 猪猪不领取；解除后只检查仍有效的任务 |
| U18 | 昨日最高温 18℃，今日分别为 13℃、14℃；再删除昨日记录 | 阈值 5℃ 时仅第一组触发，同一设备同一早晨重复执行只得到一条任务 |
| U19 | 用含摄氏单位及本地预报日期的响应生成晨间快照，再在周六执行工作日规则 | 保存同城同日快照；周末不触发工作日提醒 |

代码入口为 tests/briefing-rules.test.js、tests/briefing-zaobao.test.js、tests/briefing-playback.test.js 和 tests/briefing-flow.test.js。每个参数化边界分别执行和计数。

## API 与数据库用例

| 编号 | 准备与操作 | 验收条件 |
| --- | --- | --- |
| I01 | 无 JWT 读后台；用客厅密钥访问玄关；用管理员读取设置 | 分别返回 401、403、200；设置中仅有密钥就绪状态 |
| I02 | 新建来源，试采集、正式采集、重复采集，再返回 304 | 试采集不入库；后续只有一个事件、一次模型处理；条件请求标记保留 |
| I03 | 上游超时 | 来源记录失败原因和下次尝试时间，现有事件保留 |
| I04 | 同一通勤公告由两家转载并发到达；随后运营方发恢复公告 | 转载保留两份证据、一个事件；恢复生成新播报版本 |
| I05 | 不同城市出现相似标题；非权威来源提供冲突的运行状态 | 城市分开；冲突更新只显示卡片 |
| I06 | 手动合并同设备范围的两条新闻，再将一条证据拆开 | 证据归属与事件状态同时更新；拆出的事件继承原发布状态 |
| I07 | 试采集后正式采集定向新闻，用旧版本撤回、用当前版本撤回 | 预览零投递，只有目标设备获取；旧版本 409，成功撤回后卡片及任务移除 |
| I08 | 同一设备两个页面同时领取；其他设备伪造回执；原设备重复提交同一结果 | 领取一成一败，外部回执失败，同一终态幂等成功 |
| I09 | 两个请求同时争夺最后一次模型额度；模拟模型超时 | 只预留一次。失败时卡片有来源标题，匹配的近期公告可根据设备规则提醒 |
| I10 | 对同一热搜进行连续两次不同排名采样 | 卡片更新名次，播报版本保持一致 |
| I11 | 添加未来生效的家庭事项，提前到当前，修正文案、明确重播、降级并删除 | 开始前零任务；修正不重复喊，明确重播才递增版本；降级和删除收回提醒 |
| I12 | 保存结束早于开始的事项，或指定不存在的设备 | 返回 400，数据库没有半成功的条目 |
| I13 | 关闭设备提醒、进入免打扰、推进时钟跨过过期时间 | 各情形均不能领取；到期卡片消失 |
| I14 | 先关闭再开启允许润色家庭信息 | 仅显式开启后将所选事项交给模型；多设备读取不重复生成 |
| I15 | 原条目标题保持一致，仅将生效时间从 10:00 改为 12:00 | 创建新版本，并重新执行发布规则 |
| I16 | 已产生天气任务后更换城市、调高温差或关闭降温提醒 | 无法领取先前规则产生的旧任务 |
| I17 | 模型生成家庭文案的请求尚未完成时删除原条目 | 迟到结果不重新发布已删除事项 |

## 浏览器与真实服务验收

| 编号 | 实际操作 | 通过标准 |
| --- | --- | --- |
| E01 | 用账号通过浏览器登录，打开资讯后台，查看一条自动发布的新闻并保存关注话题 | 后台状态变化，显示端出现同标题、来源和时间 |
| E02 | 打开测试场景编辑器，分别查看热点和猪猪；在绑定该场景的设备页创建一条定向家庭事项 | 编辑器有样例，设备出现真实家庭消息的完整气泡 |

| E04 | 同一显示页重建 100 次场景配置，再撤回唯一新闻 | 仅一个猪猪实例，无残留重复卡片或 JS 异常，撤回后显示空状态 |

| E06 | 验证 Open-Meteo 实时请求返回本地日期、摄氏单位和 daily.temperature_2m_max | 确认日预报服务可达；跨日阈值和缺历史值由 U18/U19 的可重复时钟夹具验证 |

## 家用版组合用例

资讯轮播验收使用两条不同类别的消息和一条无关消息。在编辑器输入两个关注词，勾选新闻和热搜，每条停留设为 2 秒并保存。在播放端检查一次仅显示一条标题、来源、简述，无操作自动切换，轮播到第二条时刷新数据仍停在该条。检查小尺寸卡片没有滚动条，无匹配、撤回和过期时不会残留旧标题。切换到仅新闻或仅热搜时应只播放所选类别，关注词留空时播放所有符合全局偏好的消息。

| 情景 | 操作 | 预期结果 |
| --- | --- | --- |
| 多类同时启用 | 保存家庭、降温、新闻三项，注入同一时间窗的三种任务 | 三类均可进入同一设备的队列；关闭新闻和家庭后仅剩降温，资讯列表仍可阅读 |
| 两类话题 | 添加关注「中国」、排除「娱乐」，采集新加坡本地报道、北京交通公告和北京娱乐报道 | 仅北京交通公告可上屏，排除条目不生成摘要；清空关注后仍尊重排除列表 |
| 语义筛选 | 关注「影响苏州通勤的事件」，排除「娱乐花边」，同时采集姑苏区封路公告和标题借用关注词的艺人新闻 | 封路公告可试采集、发布和上屏，艺人新闻被排除；刷新复用模型对两条的判断 |
| 回退与恢复 | 分别令次数耗尽、令牌不足、供应商报错、模型返回条数不全；恢复后重采相同 RSS | 当次关键词命中的条目可发布并报告回退原因；恢复后可以补收此前仅在语义上相关的条目 |
| GLM 截断 JSON | 首次调用耗完输出额度且有实际用量，第二次返回完整布尔数组 | 在共享额度内用较大的输出额度重试一次；成功时采用语义结果，两次按实际令牌用量结算 |
| 来源与组件 | 给热搜来源设置地区「苏州」和关注词「交通管制」，给两个组件分别设置「出行」和「体育」 | 姑苏区绕行的热搜只在「出行」组件出现，另一组件不播放；重复读取复用判断 |
| 热搜合并与迁移 | 在已有单条热搜卡的来源采集两条同轮暴雪预警和一条独立台风消息，再交换排名 | 显示端仅轮播两个事件；原始报道可追溯，换排名不改变卡片编号或版本，重复采集复用判断 |
| 预警变化 | 用全新链接依次报道北京暴雪升级和解除 | 沿用原事件编号，版本各增加一次，轮播只出现最新预警 |
| 归并降级与撤回 | 让模型返回重复成员编号，加入新热搜，恢复后再次采集；再人工撤回事件 | 降级保留已知关联，未知条目单列；恢复后归入原卡，无实质变化保持版本；撤回的已知标题不上屏 |
| 存量与撤回 | 对已发布的资讯更改话题，尝试领取旧新闻，再清空列表 | 上屏和播报立即采用新偏好，已撤回内容不会重新出现 |
| 样貌持久化 | 选择兔耳猪并应用，验证 16 个造型的待机画面，禁用 WebGL 后重新加载播放页 | 16 张画面不同；设备和预览使用相同样貌，回退后的兔耳猪仍可挥手 |

## 3D 玩偶回归

以下用例在 `tests/browser/briefing-smoke.js` 的独立内存库中运行。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 旧画面升级 | 打开未设置形象的伙伴，在编辑器选择 3D 玩偶并应用更改 | 原先显示 2D，切换后预览显示戴围巾的 3D 猪猪，播放端加载 3D 模型 |
| 动作 | 渲染待机、挥手、指示、围巾和严肃五种姿势，点按常驻玩偶 | 五幅渲染结果不同，挥手过程中手臂位置随时间变化 |
| 问候与节假日 | 在组件时区跨过五分钟或午夜，检查春节、中秋、国庆假期及调休工作日；在轮换时推送重要提醒 | 待机文字随时间变化，节日祝福和假期问候按当地日期出现；问候不发声，提醒字幕不会被问候覆盖，结束后恢复当前时段的文字 |
| 资讯与提醒 | 打开场景、点击待机猪猪，发布相关资讯和家庭提醒，再紧急插播 | 气泡默认可见，点击后仍显示问候；相关资讯和家庭提醒自动显示字幕，播完恢复问候，紧急插播优先 |
| 兼容模式 | 在新浏览器页面禁用 WebGL，再加载同一设备 | 显示 2D 插画，点击后切换到挥手插画 |
| 重建 | 连续重建场景 100 次，依次移除资讯和伙伴组件 | 只显示一个玩偶，单独的伙伴可以读资讯，移除伙伴后资讯组件可以继续显示 |

## 家庭助手与自动跟进

| 用例 | 操作及输入 | 预期 |
|---|---|---|
| A01 建档 | 在「家庭资料」填写路线和工作时段，保存并刷新；两个浏览器分别修改同一旧版本 | 资料保留；旧版本返回 409，不覆盖新版本 |
| A02 对话记忆 | 聊天说「下个月 12 日坐 MU5123 从上海虹桥去北京」；用相同请求号重发 | 在家庭时区解析为下一个自然月的 12 日；一条对话、一项计划。重新打开网页仍可见 |
| A03 封路 | 给虚构家庭设置经过青禾路的通勤路线，发布青禾路封闭施工和无关展览 | 猪猪自动提示绕行，展览只出现在资讯列表；不需要点击猪猪 |
| A04 航班风险 | 发布与上述行程日期、机场吻合的罢工预告；同时发布去年罢工回顾 | 仅预告送到屏幕，并建议核实；不能把“可能取消”报成航班确认取消 |
| A05 没有依据 | 模型判断有关，但给出新闻里没有的引文；或没有家庭资料、只有过期计划 | 没有提醒；没有可用资料时也不调用判断模型 |
| A06 停止跟进 | 在聊天页取消计划、改成其他通勤路线、撤回新闻或发布恢复通行公告 | 旧判断不再可领取；恢复通行公告触发重新判断；资讯列表仍独立工作 |
| A07 持续影响 | 将设备设为间隔 1 分钟、最多 2 次。模拟两台浏览器同时领取同一设备任务 | 到间隔前不能重复领；到点后只有一个领取成功；第一次的延迟请求和回执不会消耗第二次；到上限不再提醒 |
| A08 模型不可用 | 让模型超时或无配额，再发送计划或分析资讯 | 网页说明失败，未成功的计划不入库；不把未判断的资讯播报出去 |
| A09 网页与屏幕 | 浏览器录入路线、发消息、取消计划；在有猪猪的设备上触发家庭事项，再紧急插播 | 网页操作持久化，设备自动显示字幕；紧急插播可以中断 |
| A10 自由记忆 | 打开原先有地址和路线的家庭，改成带标题、缩进和换行的自由文档，再清空 | 原资料自动可见；格式保留；聊天和影响判断使用新文档，清空后旧资料不会复活 |
| A11 独立聊天 | 在手机尺寸的浏览器打开局域网链接，取昵称、发送、刷新；第二个浏览器使用同名和相同请求号 | 各自只看到自己的历史；另一浏览器不能读或取消前者的行程；无需后台登录 |
| A12 访问控制 | 非本机网段、外部 Host、跨站来源、伪造转发头或过期 Cookie；访客请求审计 | 不允许外部访问；失效会话不能发消息；访客不能读取审计 |
| A13 审计 | 后台和访客各发消息，再模拟模型失败和重试 | 管理员可按时间翻页看到消息、回复或失败、时间、访客自填称呼、会话编号和 IP；模型调用前已保存原消息 |
| A14 组件隔离 | 同屏绑定两个猪猪场景；一个关闭家庭事项，另一个开启。同一组件也绑定第二块屏幕 | 場景切换按当前组件选择规则；相同组件跨屏共用规则，领取和回执互不占用；未绑定组件不得领取 |
| A15 机场定时提示 | 从独立聊天发送“明天早上八点提醒我准备出门去机场”，刷新、重试同一消息 | 定时提示列表只有一项，日期和时区正确；运行定时任务会向目标屏幕发送提示开始事件 |
| A16 限时充电留言 | 在同条消息里请猪猪在明天 18:00 至 23:00 提示给特斯拉充电 | 信息列表正确写入起止时间；聊天审计同时列出定时提示和信息的真实 ID |
| A17 操作边界 | 模型申请未知操作、过期时间、没有原文依据，或在资讯查询中夹带写入请求 | 无效的一组全部不写入；纯资讯查询无法创建系统记录 |
| A18 查看和改期 | 从原聊天创建 08:00 机场提醒，查看后要求推迟半小时，再重试同一请求 | 编号和时长保留，只有 08:30 的任务；后台审计可见原时段与新时段 |
| A19 信息与取消 | 修改充电信息正文，保留原时段，然后取消信息与机场提醒 | 信息列表及时更新，原定时任务解除，取消审计保留删除前的记录 |
| A20 所属会话与并发 | 同名事项、其他访客创建、管理员手工添加、模型误提新建、处理期间由后台修改 | 多个匹配时追问编号，越权和重复创建受阻；并发编辑保留先提交的改动并返回 409 |
