# 猪猪模型气泡与独立记忆

## 使用方法

在「猪猪伙伴 → 气泡生成设置」设置全局免打扰和每天12个两小时时段（00–02、02–04，直到22–24）。每段独立填写0–120整数分钟；0表示该时段暂停生成，保留已有普通问候，没有可保留问候时显示暂停状态，1–120表示间隔分钟。时段使用家庭时区。旧单一间隔自动作为12段初值，超过120按120兼容读取，不修改原配置；未配置时各段默认5分钟。

所有猪猪组件共享一个模型决策和气泡ID。多个组件并发请求只调用一次模型，新结果通知所有屏幕，30秒轮询兜底。字号、形象、声音与音量仍按组件独立设置。同一屏幕切换多个猪猪组件不会重复朗读同一决策，不同屏幕分别记录展示和朗读回执。家庭资料、天气、新闻、信息和提醒统一作为家庭上下文；提醒类型按已绑定组件启用类型的并集生成。

气泡文字超出可视区域时自动缓慢向上滚动，保留组件设置的字号与原气泡尺寸，不显示滚动条。开头和末尾各停留一段时间，再循环展示；短文字保持静止。更换话语从头开始，组件尺寸变化后自动重新检测。该效果只影响本地展示，不触发额外模型调用。

全局免打扰支持开关及跨午夜时段（例如22:00–07:00），开始与结束相同表示不静默，覆盖组件的旧免打扰字段。未保存全局设置时从首个已绑定猪猪组件继承旧时段；之后以全局设置为准。免打扰期间不朗读或主动提醒，但启用时段仍可生成陪伴。若希望完全不调用气泡模型，请将相应时段设为0。暂停期间资料更新或prompt修改也不会绕过暂停。时段/免打扰边界仍约束提醒；普通问候保留到下一条生成。两者都不会提前调用模型。

自动生成严格遵守配置间隔：下次允许时间=数据库中上一轮生成开始时间+当前时段的分钟数。天气、资讯、家庭资料及系统事项变化仅供下一轮生成使用，不触发额外调用；跨时段、跨午夜、页面刷新、多屏请求和服务重启均不重置计时。普通问候不因模型给出的短有效期而清空，直到下一条成功生成再替换；更新失败、0暂停或重启也可继续展示同一条。实际提醒到期、取消或引用事项被修改时仍立即撤下，返回waiting状态等到下次生成。模型自身的nextReviewAt/validUntil不能缩短间隔。没有启用屏幕请求时不会为了补齐错过的周期连续生成；屏幕30秒轮询，因此实际生成可能稍晚于到点时间。显式保存/恢复system prompt仍按原功能立即使用新版本（0时段除外），这是管理员操作，不是上下文更新触发。

每句话，包括普通问候，由共享模型设置中的GLM/DeepSeek生成。上下文包含当地日期、时区、农历和内置假期表、完整家庭资料、有效计划、独立记忆、天气观测、今天加未来7天日预报、48小时预报、官方预警、最多60条当前有效资讯、系统信息与定时提示、近期展示记录。缺少或过期的数据会标明状态。模型选择话题、重要程度、动作、有效期及是否再次提醒；旧固定问候和温差阈值不参与实际气泡播报。

系统默认提示词：[pig-screen-system.md](../src/prompts/pig-screen-system.md)。在「猪猪伙伴 → 气泡 System prompt」可查看、编辑、保存当前完整文本，也可直接恢复默认版本。自定义内容保存到数据库，重启和升级不会覆盖；保存/恢复后通知屏幕并使旧气泡缓存失效，新生成无需等原间隔，也无需重启。进行中的旧版本结果会被拒绝。多页面同时修改时，版本冲突返回409，页面保留草稿，避免互相覆盖。请保留JSON输出格式要求。聊天审计记录实际使用的自定义提示词。

提示词中单独一行 `speechMaxChars: 40` 控制话语长度，范围1–180，省略时默认40。汉字、标点、数字、英文字母、空格、换行及emoji均按Unicode码点计数，JSON元数据和审计reason不计入。超过上限时要求模型重写完整短句，最多一次；不截断正文。两次均不合格则本轮不发布，也不能靠后续轮询绕过生成间隔。两次真实请求各有一条审计，但只会发布最终合格的一个决策。

家庭功能开关、免打扰、设备绑定、到期校验、请求去重和音频解锁仍由程序执行。免打扰期间只生成陪伴，不朗读。模型不可用或额度不足时显示明确服务状态，不用固定问候冒充模型输出。

## 独立记忆

示例：“明天早上提醒我拿红包，不要在系统添加提醒，只记在你自己的记忆里，明天中午忘记。”

- 猪猪新增独立记忆，回复说明有效期，不写`timed_reminders`或`info_items`，也不把它塞进家庭计划。
- “明早”没有明确时间时，提示词允许使用次日06:00–12:00，并结合已有作息；模型生成时优先考虑有效期内尚未播报的明确托付。
- “把红包事项推迟半小时，到期时间不变”：保留原ID，开始时间精确增加30分钟，保留结束时间。
- “查看你自己记住的事项”“取消红包记忆”：通过聊天查看和取消；同一访客只能管理自己写入的记忆。
- 临时记忆必须有到期时间；明确要求长期记住的事实可以无到期时间。用户提供的家庭基础资料仍由「家庭记忆」单独维护。

有效记忆保存在数据库`pig_agent_memory`，同时生成`data/pig-agent-memory.md`（权限600）的可读镜像。文件不是手工编辑入口，请通过聊天修改。启动时重建，后台每30秒和每次读取时清除到期条目；聊天、操作和自动到期的审计保留，不再参与当前有效记忆。可以用`PIG_MEMORY_PATH`改变镜像路径，需随数据卷持久化。

数据库触发器让记忆变化、聊天回执、版本更新和操作审计原子提交。重复`requestId`不会重复新增；修改取消必须使用本人原ID及版本；模型调用期间发生取消或到期，旧气泡不可发布或领取。文件投影与数据库分离，进程重启可从数据库恢复，避免文件损坏丢记忆。

这是在线助手的提醒能力，依赖屏幕在线、可用模型和允许的功能。需要精确闹钟或强制插播时，明确说“创建系统定时提示”。

## 聊天审计

「猪猪伙伴 → 聊天审计」支持：全部类型、用户对话、自动气泡完整对话、仅System prompt、仅模型上下文、仅模型返回；还可按用户会话筛选。同名访客用不同会话编号区分，用户昵称不是身份凭证。

每次真正生成气泡前记录实际system prompt、完整上下文、模型名称；模型返回后记录原始响应、结果和失败原因。JSON无效、预算用完、上下文变更也保留审计。缓存复用不会伪造一次新的模型调用。仅管理员可以读取这些包含家庭资料的记录，访客聊天接口不暴露系统审计。

「猪猪自己的记忆」默认以完整文本显示有效记忆，可选中复制，也可切换为列表，包含内容、生效时间、到期时间与编号。文本采用与Markdown镜像相同的格式，读取前清除到期条目；只读查看不修改记忆。下方保留最近50条记忆操作。「气泡判断记录」显示最近30条话语、模型理由、有效期和实际展示/朗读结果。

## 接口

前缀`/api/v1`。管理员接口使用JWT，屏幕接口使用`X-Device-Key`。

| 接口 | 用途 |
| --- | --- |
| GET/PUT `/companion/settings` | `greetingSchedule`为12个0–120整数；`quietEnabled/quietFrom/quietTo`全局免打扰；只读`zone`为家庭时区。旧`greetingMinutes`写入1–120时填充全部时段，读取返回当前段值；`familyAI`兼容 |
| GET `/companion/agent/memory` | 有效记忆、镜像位置、最近50条记忆审计 |
| POST `/companion/agent/messages`、`/pig-chat/messages` | 聊天管理独立记忆；沿用`message`和`requestId` |
| GET `/companion/agent/narration-prompt` | 返回`prompt/defaultPrompt/isDefault/revision` |
| PUT `/companion/agent/narration-prompt` | 保存传`{prompt,revision}`；恢复默认传`{reset:true,revision}`；文本1–20000字符，空白拒绝，版本冲突409 |
| GET `/companion/agent/narrations` | 最近30条决策与展示回执 |
| GET `/companion/agent/audit?type=system_prompt&scope=system:narration` | 审计筛选；`before`分页；响应`users`用于会话选择 |
| GET `/devices/{id}/narration?componentId=…` | 模型气泡，包含`id/speech/action/validUntil/nextReviewAt/preferences` |
| POST `/devices/{id}/narration/{event}/claim` | 传`componentId`，校验共享上下文、设备绑定和有效时段；`accepted`表示本屏幕是否首次领取该共享话语 |
| POST `/devices/{id}/narration/{event}/result` | 传`componentId/result`；结果为`subtitle/spoken/interrupted` |

旧`briefing`和`deliveries`接口仅用于兼容；新展示端不再使用旧天气风险候选与资讯影响阈值选择播报。天气数据获取、来源缓存和新闻订阅保持原流程。

### 固定间隔与40字符专项（2026-11-09）

根因：旧缓存依赖完整上下文指纹，并把模型有效期/时段边界当作下一次生成时间；天气或资讯刷新就可能让30分钟设置提前失效。现将展示有效期与生成计时分离，以持久审计为生成时钟，不增加或改写用户配置。

`tests/pig-narration-cadence.test.js`覆盖：

| 场景 | 预期 |
| --- | --- |
| 30分钟内每30秒双屏轮询，持续改变天气/资讯/家庭资料 | 第30分钟之前只有一轮调用；到点并发请求只生成一个新ID |
| 生成过程中天气或无关资讯刷新 | 不将本轮误判为失败，不因刷新启动第二轮 |
| 模型只给1分钟有效期或较早nextReviewAt | 旧句到期停止展示，仍等满30分钟 |
| 已引用事项修改或取消 | 拒绝旧句领取并返回waiting，不提前生成 |
| 跨两小时时段、跨午夜、0暂停恢复 | 上次调用计时保留；配置改为60/15分钟则以上次调用加新值计算 |
| 模型失败、上下文变化、重新加载服务模块 | 从数据库恢复计时，失败也不触发频繁轮询重试 |
| 40/41字符及标点、空格、英文、数字、emoji | 边界正确；超限仅重写一次，失败与成功分别审计，不截断 |
| prompt改为50、重复超限或非法配置 | 新上限直接生效；不合格结果不发布；非法/重复配置拒绝保存 |

### 普通问候持续展示专项（2026-11-09）

模型标为`greeting/companion`、普通优先级，且未引用具体计划、独立记忆或系统事项的话语属于普通问候；2026-11-11补齐仅引用新闻/热搜的普通陪伴（详见下方专项）。服务端返回`retainUntilReplaced:true`，旧数据中的短有效期也兼容保留；无需修改原数据库记录或system prompt。到更新时间先请求模型，旧气泡保留到新话语返回；失败不清空、不提前重试。0时段保留已有普通问候但不调用、不朗读。引用具体事项的陪伴话语仍按提醒处理，不因模型标签而保留已失效内容。

### 新闻陪伴被误撤下专项（2026-11-11）

线上15:48:30生成的一条油价话题被模型判为`companion/normal`，固定下次更新时间为16:48:30，但程序因其引用新闻而按提醒处理，把有效期裁到16:00时段边界。此前只覆盖日期、资料、天气的普通问候保留逻辑遗漏了新闻。此外，热搜采集会续期缓存或更新排名，严格比较引用对象也可能误撤下普通陪伴。
