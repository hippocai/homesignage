# 热点速览与屏幕伙伴详细设计

HomeSignage · 初稿与已交付行为对照 · 2026-11-06

当前版本自动发布资讯。全局感兴趣列表命中任一项即可，不感兴趣列表优先。猪猪组件独立保存家庭事项、按城市判断的降温和影响家庭的新闻提醒。场景组件支持 16 款样貌，2D 和 3D 共用选择；气泡按组件时区每五分钟轮换问候，优先显示已领取的重要提醒。家庭记忆、局域网聊天、系统记录修改及审计的验收见[系统回归测试](系统回归测试.md)。下文涉及人工审核、按设备单独配置的部分为早期方案。

客厅屏用「热点速览」展示最近值得看的事，玄关屏用「屏幕伙伴」在合适的时间提醒出门的人。管理员选定来源、主题和设备，两种功能共用一套模型设置，分别控制显示和播报。建议分两期交付，以下阈值、时段和容量均为待审的首版默认值。

## 1 家里会怎样使用

| 场景 | 屏幕上的表现 | 管理员可以控制 |
| --- | --- | --- |
| 早餐时看新闻 | 客厅卡片显示三条标题、来源和时间。置顶消息多一行摘要，点击可看详情和原文 | 主题、地区、条数、字号、来源、有效期 |
| 临出门遇到降温 | 玄关玩偶裹上围巾，字幕显示“今天预计最高 12℃，比昨天预报的最高温低 6℃。出门带件外套吧。” | 城市、温差、提醒时段、工作日、音量 |
| 家里发了一条重要事项 | “今晚 8 点至 10 点停水”到生效时间，指定屏幕上的玩偶招手提醒，字幕保留起止时间 | 信息等级、有效期、播报设备，可预听台词 |
| 通勤线路临时停运 | 来自运营方的公告置顶。只有订阅这条线路且允许主动提醒的设备才播报。恢复运营时替换原卡片 | 指定可信发布机构和关注线路、手动撤回、解除置顶 |
| 某话题进入热搜 | 卡片显示平台、名次和采样时间。热度本身只影响卡片排序 | 启用具体榜单、关注词、屏蔽词 |

## 2 配置与审核界面

后台新增「资讯与伙伴」入口，场景编辑器新增两个可独立拖放的组件。首次使用按“添加来源 → 试采集 → 预览 → 选择场景和设备 → 开启发布”操作。默认开启预览模式。模式切换只影响之后进入发布流程的版本，历史候选可逐条发布，避免第一次启用就把旧新闻全部推上屏。

| 位置 | 控件和反馈 |
| --- | --- |
| 来源与主题 | RSS/Atom 填订阅地址，Brave 填查询词、国家或语言，榜单选择已配置的平台。每个来源可试采集，看到最近三条、原文、上次成功时间、失败原因、下次重试。可信机构由管理员单独指定 |
| 事件审核 | “待审 / 已发布 / 已结束”三个视图。展开可对照原文片段、来源、关联报道、命中规则、拟发布设备、卡片与台词。支持改摘要、确认发布、合并、拆分、撤回、屏蔽主题。预览和试听只在后台发生 |
| 模型与用量 | DeepSeek 和 GLM 二选一，填写模型标识、测试连接。显示当日搜索次数、模型请求数、令牌用量、失败数及预算余量。默认不同供应商之间由管理员主动切换 |
| 信息列表 | 新增“由屏幕伙伴提醒”和目标设备选择。可在生效前修改或撤销。旧条目默认关闭播报；选中设备决定播报范围，原有列表仍按已有规则展示 |
| 设备详情 | 启用伙伴、设备时区、声音开关、音量、播报窗口、免打扰、最短提醒间隔、测试声音。显示上次结果，例如“已显示字幕，设备声音未解锁” |
| 场景编辑器 | 热点组件选主题、类别、条数（1–5）和版式。伙伴组件选形象、位置、大小、常驻或有事出现。一个场景最多一个伙伴；预览使用样例或已选事件，并明确标注 |

热点卡片默认按置顶、重要性、最新实质更新时间排序。无匹配时显示“暂无符合条件的资讯”，采集失败且有有效内容时保留卡片、显示上次更新时间。卡片过期即移除。可触摸设备点开详情，返回后继续当前场景。后台总能查看原文链接。

## 3 来源采集与事件判断

沿用现有 Node.js 服务和 SQLite。后台定时采集一次，结果供多块屏共享。数据依次经过来源适配、去重、事实提取、规则判断和发布。SQLite 保存发布状态，Socket.IO 只通知目标设备拉取最新结果，重启后可恢复。

| 来源 | 采集约定 | 时间和证据 |
| --- | --- | --- |
| RSS / Atom | 默认每 10 分钟一次，利用 ETag 或 Last-Modified 减少下载。按 GUID、规范化链接识别重复条目，提取纯文本 | 分开保存来源发布时间、采集时间、事件发生时间。缺发布时间标“发现于”，过旧或时效不明的消息进入待审 |
| Brave News | 每条启用查询默认每 30 分钟一次，限定地区、语言和最近时段。按配额轮询；后台估算每天请求数，例如一条全天查询约 48 次 | 保留发布机构、文章链接和允许使用的摘要。搜索发现时间不作为事件时间；启用前按所选套餐核对展示与留存权限。[Brave News 接口](https://api-dashboard.search.brave.com/api-reference/news/news_search/get) |
| 平台热搜 | 适配器输入为平台、榜单、主题、名次、榜单链接及采样时间。支持有权使用的榜单接口或订阅源；暂无来源时隐藏排名选项 | 同平台、同榜单、同话题更新名次，最近一次采样超过两个轮询周期标为过时。首个真实平台待选定数据源后联调 |
| 家庭信息与天气 | 家庭信息通过本地写入和生效时间触发。天气按已启用的降温规则采集，玄关即使没放天气组件也能触发 | 家庭信息关联原条目及版本，天气关联城市、供应商、预报日期和采样时间 |

**合并与实质更新。** 先用来源标识、链接和正文摘要指纹排除重抓。跨来源在同主题、地区和时间窗口内比较发布主体、对象、状态及生效日期。日期、地点或线路矛盾时保留为候选，交管理员判断。转载保留证据链接，只更新来源数。运营方从“暂停”改为“恢复”、生效时间改变或管理员明确更正，才生成可再次提醒的新版本。榜单名次波动、标题润色、媒体重复引用同一公告均不增加播报版本。

**可执行的发布规则。** 管理员屏蔽或内容过期优先过滤。普通热点命中订阅即可进入卡片。匹配地区和关注主题可置顶。主动新闻提醒还须同时满足指定权威来源、明确的影响对象及有效时间、已开启的设备规则。每次保留具体命中项。仅有热度、匿名传闻、相互冲突的来源、缺少生效时间的高影响公告均进待审。管理员确认后可以定向发布；全屏紧急插播沿用现有人工入口。

## 4 模型输入与输出

服务器为两个功能提供同一个模型入口。任务一将新闻标题和允许使用的来源片段整理为摘要与事实，任务二基于已通过规则的事实写一句台词并选择预设动作。相同事实版本、语言、模型、提示模板的结果可复用。第三方文本只作为待分析资料，不参与定义规则，也不直接传入设备控制接口。[DeepSeek 结构化输出](https://api-docs.deepseek.com/guides/json_mode/) · [智谱结构化处理示例](https://docs.bigmodel.cn/cn/best-practice/case/ai-search-engine)

新闻输出包括短标题（最多 32 个汉字）、摘要（最多 90 字）、主题、地区、关键事实及各自的证据编号。台词最多 60 字，只接收已有证据编号和预设动作。日期、温度、地名、线路、事件状态等关键值要与来源或规则计算结果核对。高影响状态优先用结构化字段填入固定句式。输出超时、字段缺失、凭空增加停运范围等情况，丢弃生成结果；普通卡片使用可展示的原标题，重要消息进入待审。

家庭信息可能含有住址或行程，默认本地按原文生成提醒；管理员开启“允许模型润色家庭信息”后，才发送勾选播报的正文。设备密钥、设备名、住户身份和设备列表不进入提示词。语音首版使用设备可用的系统中文朗读能力，设备无合适语音或播放被拦截时仍显示完整字幕，并在设备详情记录原因。后台可在目标设备测试实际发音。

## 5 天气与家庭信息触发

**降温。** 现有两个天气适配器向上层提供的是实况温度。新增逐日预报能力，先在一个支持日最高温的数据源上完成联调；后台显示该城市是否可用。首版以本地 07:00 为晨间快照时刻，保存同一地点、供应商、预报日期、指标和单位的当日最高温预报。取快照前 3 小时内最新的有效预报，每日固定一份。早晨 07:00–09:00 以“昨日晨间快照 − 今日晨间快照 ≥ 5℃”触发，各设备按本地时区和规则窗口执行。文案明确比较的是两次预报。缺昨日记录、城市或供应商变更时重新积累；界面显示“等待两天同口径预报”。首版工作日指周一到周五，提醒窗口和温差可调。

**家庭信息。** 保存带目标设备的 important 或 urgent 条目后，在生效窗口开始时创建提醒，无开始时间则立即生效。发布前校验结束时间晚于开始时间。降级、删除、取消播报或缩短有效期会撤销未播任务并关闭已显示的对应气泡。修正错别字仅刷新字幕；需要重播的更正由管理员明确勾选。服务启动时补查仍有效且已启用的条目，按条目、版本及设备去重。urgent 优先于普通伙伴任务，管理员紧急插播仍有最高优先级。

## 6 屏幕播放与中断

首版提供一款本地随包分发的 2D 玩偶。用少量透明图层或精灵帧渲染待机、招手、围围巾、指向卡片、认真提醒五种动作。场景中猪猪和气泡常驻，待机显示问候，收到相关资讯或家庭提醒时自动显示字幕，播报结束后恢复问候。声音默认关，设备上可点击“启用声音”并试播。动效、字号和台词可在编辑器预览。减少动画设置开启时显示静态姿势。

| 设备状态 | 播放决策 |
| --- | --- |
| 当前场景里有伙伴，窗口有效 | 每次只显示一条。家庭 urgent 优先，其次是定向重要事项、重大新闻、天气。相同优先级按最早到期排序。字幕默认 10 秒，较长台词按阅读或朗读时间延长至最多 25 秒 |
| 当前场景没有伙伴 | 保留有效待播任务，下次切到有伙伴的场景再检查。全天没有伙伴的设备在配置时提示。热点卡片可以单独工作 |
| 设备免打扰或关闭声音 | 免打扰只允许静态卡片，跳过主动提醒；单独关闭声音时仍允许动作和字幕。建议夜间 22:00–07:00 免打扰 |
| 多条消息连续到达 | 默认每台设备主动提醒至少间隔 10 分钟，窗口结束或过期则丢弃。家庭 urgent 可跳过该间隔，仍遵守免打扰 |
| 定时提醒或紧急插播出现 | 有声定时提醒占用声音时伙伴让出声音。紧急插播立即停止伙伴语音、隐藏气泡。已开始的任务记为中断，清除警报后只检查尚未开始且有效的任务 |
| 场景切换、刷新、断线 | 清理上一场景计时器及语音。屏幕重新鉴权后拉取当前有效卡片与待播任务。已开始的任务不自动重复，过期任务不追播 |

声音是否真正被人听到无法从浏览器确认。后台分别记录已领取、已显示、朗读结束、仅字幕、中断、过期。预览不写入生产设备的投递记录。

## 7 数据设计与投递一致性

新增数据沿用 SQLite，绝对时间保存为 UTC，比较预报日期和安静时段时转换成对应 IANA 时区。管理设置放在现有 settings 白名单中，设备偏好沿用 devices.config，组件样式和布局沿用 components。拟新增的数据如下。

| 记录 | 主要字段与约束 |
| --- | --- |
| 资讯来源 news_sources | id、类型、配置、启用状态、信任机构、轮询周期、下次抓取、条件请求标记及最后错误 |
| 来源条目 source_items | source_id、外部标识、规范链接、摘要指纹、发布与发现时间、许可范围内的证据片段、关联事件；来源与外部标识唯一 |
| 事件 events 及版本 event_versions | 稳定事件 ID、主题和地区、当前版本、审核状态；每个版本保存事实、证据引用、卡片、台词、动作、发生时间、有效期和变更原因。事件与版本号唯一 |
| 提醒规则 companion_rules | 事件类型、匹配条件、目标设备或组、启用状态、窗口和规则版本；信息条目的播报选择以条目 ID 关联，删除级联取消 |
| 每设备任务 deliveries | 事件、播报版本、设备、可领取时间、到期时间、领取标识、播放结果与时间。事件、播报版本、设备三者唯一；索引覆盖设备、状态和到期时间 |
| 日预报快照 weather_daily_snapshots | 城市标识、时区、供应商、当地日期、快照时刻、单位、最高温和预报更新时间；同一地点、供应商、日期与快照时刻唯一 |
| 用量及操作记录 | 按日期/供应商记录预算预留与实际用量；审核、编辑、撤回记录操作者、时间、版本及原因。日志隐藏凭据。建议设备记录保留 30 天，采集内容按来源允许的期限清理 |

事件状态依次为候选、待审或已发布、已撤回或已过期。首次发布及每次实质更新都在一个数据库事务内保存版本并创建目标设备任务；提交后再发 Socket 通知。定时对账会补发通知，设备也可主动同步。接口对审核版本做乐观锁检查，同时编辑时返回冲突并展示新版。撤回立即使卡片和待播任务失效，并通知在线设备停止对应气泡。

播放采用“宁可漏一次，也不重复喊”的策略。客户端准备显示前向服务端领取，服务端在同一事务内校验设备、时段、版本、过期和领取状态，只允许一个页面成功。领取成功后浏览器崩溃会留下“已领取，播放未确认”，不自动重发。由管理员显式发起再次提醒。单个设备的多个浏览器页、重复推送和服务重启均使用同一条唯一记录。

## 8 接口与项目接入点

下表为拟议接口，路径均以 /api/v1 为前缀。管理端用管理员 JWT；设备接口逐次校验 X-Device-Key 与路径设备的对应关系，服务器据此限定可读取的场景及任务。

| 接口 | 行为 |
| --- | --- |
| GET/POST /news/sources，PATCH/DELETE /news/sources/:id，POST /news/sources/:id/test | 管理来源；测试只返回样例与状态，调用计入预算 |
| GET /news/events，GET /news/events/:id，POST /news/events/:id/actions | 分页筛选、查证据、按 expectedVersion 审核、编辑、合并、拆分、撤回。发布操作支持幂等请求标识 |
| 场景组件新增/修改接口 | 猪猪的 config.reminders 保存提醒类型、朗读、免打扰、重复及降温规则。独立后台维护记忆、聊天和审计；设备旧规则接口不再接受写入 |
| GET/PUT /settings，POST /news/model/test | 白名单增加供应商、模型名、预算、预览模式；凭据在服务端环境中配置，管理端只返回是否就绪 |
| GET /devices/:id/briefing | 返回该设备可见卡片及适用组件、有效待播任务、服务端时间与有效期。设备启动、重连、收到通知时同步，在线时每 60 秒兜底核对 |
| POST /devices/:id/deliveries/:taskId/claim 或 /result | 原子领取或上报结果；同一回执可重复提交，其他设备不能领取。过期、撤回和已领取分别给出原因 |

在 src/index.js 初始化采集与发布任务，在 src/services 管理模型调用、天气快照、规则和投递。扩展 infoItemController 的写入路径，将条目变化与待处理事件一起持久化。socketService 沿用设备房间，新增 briefing-updated 通知（只带版本提示）。管理界面接入 SceneEditorView、InfoItemsView、DevicesView 和 SettingsView；显示端在 client/js/main.js 的场景装载、卸载、断线和紧急插播入口统一控制伙伴。后台预览和显示端复用同一个卡片与动作渲染器。

## 9 成本与故障处理

搜索按查询计划预估次数，模型按去重后的新事件调用。首次启用外部付费服务时设置每日请求与令牌上限；执行前预留预算，并发任务不能绕过上限。超额后暂停该供应商至次日，RSS、手工事项、本地模板继续运行。后台区分“预算耗尽”“凭据无效”“网络超时”“来源无更新”。

RSS 请求仅允许公网 HTTP(S)，解析 DNS 并在连接和每次重定向时校验目标，拒绝环回、内网及元数据地址。限制响应大小、解析时间，关闭 XML 外部实体，屏幕以纯文本显示片段。模型与 Brave 只连指定供应商。单来源抓取互斥，超时和限流退避，遵守 Retry-After。失效凭据暂停该来源并提示管理员。推荐新闻卡片默认 24 小时过期，明确的结束时间优先；新闻主动提醒默认 30 分钟内有效，天气到当次出门窗口结束，家庭信息取配置结束时间，无结束时间时主动提醒最多保留 24 小时。

## 10 分期交付与验收

一期交付采集、模型切换、事件审核、热点组件和设备定向发布。二期交付伙伴组件、系统中文朗读、天气和家庭事项规则、设备领取与中断处理。平台热搜适配以取得可用且允许展示的具体来源为联调前提。首版建议用一台玄关屏、一台客厅屏试运行，再启用自动发布。

| 验收情境 | 通过标准 |
| --- | --- |
| 同一公告来自 RSS 和 Brave，另有相似标题但不同城市的新闻 | 前两条合并成一张卡并能追溯来源，不同城市各自保留。来源冲突进入待审 |
| 模型生成的时间和公告不一致，或两个供应商分别超时 | 错误台词不发布。普通卡片可显示原标题，手工重要事项仍可使用原文提醒 |
| 预览后定向发布，再撤回 | 预览时所有真实设备零投递。局域网正常时以提交后 3 秒内更新在线目标屏为验收目标；未订阅屏不显示。撤回同步移除卡片和待播任务 |
| 线路停运、十次转载、随后恢复 | 只生成停运和恢复两次可播版本，最新卡片显示恢复状态。热搜排名变化只更新卡片 |
| 昨日 18℃、今日 13℃，阈值为 5℃；再分别测试差 4℃、缺昨日值、城市改变 | 第一组在有效时段提醒一次，后三组均不触发。台词数值可与两条预报快照逐项核对 |
| 家庭事项预约生效后编辑或删除 | 生效之前没有播报，仅勾选的设备可领取。取消后不播，已出现的对应气泡关闭 |
| 夜间、静音、浏览器禁止声音、紧急插播 | 夜间跳过主动提醒，静音和声音未解锁时字幕完整。插播时伙伴立即停声并隐藏，不抢占告警 |
| 两个标签页同时领取、离线跨过有效期、服务重启 | 同一设备同一版本最多开始一次。重连不播过期消息，未过期未领取的任务可恢复 |
| 连续切换 100 次场景，再用目标旧 iPad 试播 | 每次只出现一个伙伴，无重复声音、叠加监听和残留动画。触屏可解锁声音，朗读不可用时完成字幕流程 |
| 预算耗尽、订阅重定向到内网、无榜单或榜单过时 | 后台分别显示可定位的原因；其余可用来源继续工作，屏幕不产生无来源排名 |

上线时先备份 SQLite，按事务执行可重复运行的增量迁移，新功能开关默认关闭。先启用后台预览和一块测试屏，再扩展到其他设备。关闭功能时停止新采集和投递，在线屏收到通知后移除伙伴任务。设计审查优先确认首版形象与语音、重大新闻自动播报的来源范围，以及是否已有必须首发的热搜榜单。
