# 猪猪系统操作专项测试

## 目标和执行方式

验证用户通过管理后台或访客聊天，实际增删改查信息列表、创建和调整定时提示的能力。成功标准同时检查回复、数据库记录、定时任务及审计，不能仅凭猪猪说“完成了”认定成功。

测试使用独立内存 SQLite、虚拟屏幕和模拟家庭资料。真实模型验收复用线上配置的供应商及模型，凭据仅用于调用。测试不向正式屏幕投递消息。访客按浏览器会话隔离，昵称相同也不共享操作权限。

运行确定性回归：

```powershell
node node_modules/jest/bin/jest.js tests/pig-control-acceptance.test.js tests/pig-records.test.js tests/pig-chat.test.js --runInBand --forceExit
```

运行真实模型验收（先通过环境变量设置对应模型密钥）：

```powershell
$env:PIG_TEST_PROVIDER = 'glm'
$env:PIG_TEST_MODEL = 'glm-5.3-flash'
$env:PIG_LIVE_REPORT = Join-Path $env:TEMP 'pig-control-results.json'
node tests/browser/pig-control-live.js
```

测试报告包含合成对话的模型输出及逐项结果，便于复查格式错误和操作依据。不要把密钥写入用例或报告。GLM 和 DeepSeek 使用与应用一致的调用入口、额度预留和错误处理。

## 信息列表验收用例

每个需要已有信息的用例，先在当前会话创建「给特斯拉充电」，显示时间设为家庭时区的明天 18:00–23:00，并记录编号。真实聊天从 HTTP 接口进入。

| 编号 | 操作及输入 | 必须验证的结果 |
|---|---|---|
| I01 | 请在信息列表添加“给特斯拉充电”，明天18点到23点显示。 | 仅新增一条；正文正确；日期按家庭时区计算；回执、信息表、归属记录、对话和审计的编号一致 |
| I02 | 查看我的充电信息；查看我的买菜信息。 | 第一问列出充电信息；第二问返回无匹配；查询不修改记录、不消耗模型调用 |
| I03 | 把特斯拉信息的正文改成“出门前拔掉充电枪”，显示时间不变。 | 原编号、开始和结束时间保持；仅正文修改；审计记录前后值 |
| I04 | 把充电枪信息的开始时间改为明天19点，结束时间不变。 | 开始变成明天19点，结束仍是明天23点；记录总数保持 |
| I05 | 把充电枪信息结束时间推迟半小时，开始时间不变。 | 开始仍为19点，结束变成23:30；精确以原记录计算 |
| I06 | 把充电枪信息的正文改成“取消今晚充电，改到明天”，时间不变。 | 引号内完整保存为正文；原记录仍存在；时段保持 |
| I07 | 新增“记得买牛奶”，明天18点到20点显示；取消刚才那条信息。 | 只删除最近添加的牛奶信息；之前的充电信息仍存在 |
| I08 | 删除信息 #编号前8位。 | 仅删除指定且属于当前会话的记录；归属同步移除；审计保留删除前数据 |
| I09 | 在信息列表新增“取消今晚活动”，今天18点到23点显示。 | 创建新公告；正文中的“取消”不改变操作类型 |
| I10 | 先列出两条信息，再说“取消那条信息”。 | 多个候选时要求明确目标；不接受模型随意挑出的编号 |
| I11 | 把特斯拉信息显示时间改为明天晚上19点到23点，模拟模型误返回今天。 | 服务端以用户明确的相对日期和家庭时区校正开始、结束时间 |
| I12 | 同一请求编号并发提交两次，再用同一编号提交不同正文。 | 相同请求最多写入一次、回执一致；不同正文返回409；不重复创建 |

| 编号 | 操作及输入 | 必须验证的结果 |
|---|---|---|
| R01 | 请设置明天早上8点的定时提醒，内容为“准备出门去机场”。 | 日期和08:00正确，默认展示5分钟；绑定已启用猪猪组件的屏幕；调度任务存在 |
| R02 | 航班改了，明早去机场的提醒推迟半小时。 | 原编号保留，开始08:30、结束08:35；旧定时器取消；重放相同请求不再次推迟 |

## 归属、审计和异常验收

| 编号 | 前置及操作 | 必须验证的结果 |
|---|---|---|
| G01 | 访客创建并查询晚饭信息 | 同一访客 Cookie 可以查询，后台聊天会话不混入该访客记录 |
| G02 | 访客修改为“晚饭留两份”再取消 | 保持原编号；修改、取消均有成功审计及前后数据 |
| G03 | 另一个访客提供第一个访客的编号 | 无权操作；昵称相同也不改变归属 |
| G04 | 尝试操作后台手工创建的记录 | 自建记录接口不能把手工记录当成猪猪自建记录 |
| A01 | 查询、创建、修改、取消、失败和网络重试 | 每次请求记录原文、时间、会话、来源、结果；成功动作有真实编号，最终无悬挂审计 |
| A02 | 模型宣称“已删除”，但返回空动作 | 系统明确反馈未执行；不能同时回复“已删除”和“未更改” |
| A03 | 模型更新已知编号时省略type | 仅从当前会话唯一匹配的原记录补全类型；陌生编号仍拒绝 |
| A04 | 模型推断更新操作却提议create | 拒绝误建；原记录不变；失败审计可追踪 |
| A05 | 批量两项操作中一项时段非法 | 所有写入均不发生；没有部分成功回执 |
| A06 | 模型处理期间，后台修改其中一条目标记录 | 整批返回409；其他目标也不能部分更新；后台最新修改保留 |
| A07 | 模型502、429、非法JSON或连续格式无效 | 记录和家庭计划保持一致，失败原因进入审计，格式重试有次数限制 |
| A08 | 假设、否定命令和只读资讯提问 | 不生成系统记录；新闻中的指令不会成为操作依据 |
| A09 | 从旧版数据库升级 | 历史自建记录归属可恢复，已删记录或相同编号的手工新记录不会误认归属 |

## 股票刷新专项

检查组件配置持久化、设备下发、展示端定时器、服务端缓存及上游时间戳。股票频率单位为秒，允许30–3600，默认60。展示端首次挂载立即请求，每次请求结束后等待配置秒数再请求；异常时也会按该周期重试，卸载组件会取消定时器及请求。

服务端同一股票有30秒共享缓存，多个屏幕可复用最近结果。界面“行情时间”来自上游报价，和请求发生时间、服务端取数时间分别核对。休市或上游报价未变时，正常刷新也可能显示相同价格。

本次线上配置核对到已填写股票为300048，刷新60秒。在独立浏览器中加载线上股票脚本及接口，观察两次自动请求相隔60.012秒，两次均HTTP 200；服务端取数时间前进约60秒；两次上游行情时间均为2026-11-06 16:14。

## 本次执行记录

执行日期为2026-11-07。首轮新增确定性用例共10项，其中7项复现失败，涉及引号内操作词、定时修改、指代、查询结果、相对日期和虚假成功回复。真实GLM首轮17项中15项通过，另2项由一次模型省略记录类型及其后续依赖导致。第二轮遇到一次模型连接异常，已补充可理解的502错误和最多一次连接重试。

最终真实GLM验收17/17通过，覆盖I01–I08、R01–R04、G01–G02、S01否定/假设、S02不明确时间和A01审计。新增确定性专项14/14通过；整个工作区自动化回归404/404通过，Chromium及WebKit展示、轮播、股票和访客聊天回归通过。

修复包含以下行为：

- 操作识别先隔离引号内的正文，正文含“取消”也能正常新增或修改。
- 支持根据当前会话最近一次明确操作定位“刚才那条”；多条或上次查询无结果时保持澄清，不跳回更早记录。
- 精确区分开始时间、结束时间和整体时段，用户要求一端不变时保留该端。
- 改期也按家庭时区校正用户明确的相对日期。
- 查询具体主题无结果时返回空结果。
- 空动作回复不能宣称已删除或已修改。
- 已有记录的模型操作省略类型时，从当前会话拥有的唯一记录补全，陌生编号仍拒绝。
- 模型网络错误转换为可识别的502，聊天在任何写入前最多重试一次；连续失败时记录保持一致。

模型验收使用真实配置的GLM `glm-5.3-flash`，结果来自本次运行。自然语言及供应商返回存在变化，后续更换模型时应重跑真实验收。定时提醒的系统时间还通过调度器状态和回调测试验证，本次没有向真实家庭屏幕投递测试提醒。
