# 猪猪聊天入口访问控制

2026-11-10：`/pig-chat`保留家庭局域网免登录，其他入口使用HomeSignage现有系统用户名和密码登录。

## 入口判定

免登录同时要求：实际TCP客户端地址属于`192.168.10.0/24`，请求Host是该网段IP（可带端口），且没有代理转发头。支持IPv4映射IPv6地址，例如`::ffff:192.168.10.106`。`http://192.168.10.204:3000/pig-chat`从该局域网直接访问保持原体验。

域名入口、其他网段、回环地址、Docker内部地址及携带`Forwarded/X-Forwarded-For/X-Real-IP/X-Forwarded-Host/X-Forwarded-Proto`的代理请求均要求登录。不会仅凭Host、转发头或客户端自报IP授予免登录权限。容器不能识别真实LAN地址时也要求登录。

代理入口应保留原始Host；HTTPS代理可传`X-Forwarded-Proto: https`，以匹配浏览器Origin并设置Secure Cookie，该头不提供免登录权限。不要把公网请求同时伪装成LAN源地址、改成LAN Host并去掉所有代理标志；应用无法恢复被上游完全抹去的来源信息。未知代理默认不信任转发IP。

## 登录与聊天

- 使用现有`users`中的用户名和bcrypt密码，不新增默认账号或独立密码。
- 登录Cookie为随机令牌，HttpOnly、SameSite=Strict；服务端仅保存令牌哈希，有效12小时。HTTPS访问使用Secure Cookie。不在浏览器本地存储密码，不给聊天登录发放后台JWT。
- 每次获取会话和发送消息都检查入口/登录状态。单独持有旧`pig_guest` Cookie不能绕过外部登录。
- 退出会删除服务器登录记录，密码修改或账号删除也会使旧登录失效。登录20次/15分钟按实际连接地址限速，转发头不能改变限速身份。错误用户名和密码统一返回401。
- 原同源JSON、跨站请求防护、消息限速和聊天审计继续生效。
- 访客会话登录后绑定账号；换账号不会读取前一账号的访客历史。两个账号并发认领同一未绑定旧会话只有一个能成功。绑定和退出不删除历史、记忆或用户创建的系统事项。
- 外部聊天审计的actor包含真实账号及可选昵称，scope仍按浏览器会话隔离。内网未登录访客继续以昵称记录。

## 接口与兼容升级

| 接口 | 行为 |
| --- | --- |
| GET `/pig-chat` | LAN免登录或已登录返回聊天页；其他返回登录页，无聊天历史 |
| POST `/api/v1/pig-chat/login` | `{username,password}`，成功设置登录Cookie，失败401，限速429 |
| POST `/api/v1/pig-chat/logout` | 同源JSON，撤销登录并清除两个Cookie，保留历史 |
| POST `/api/v1/pig-chat/session` | LAN或已登录；返回`alias/authenticated/history`，建立或恢复访客会话 |
| POST `/api/v1/pig-chat/messages` | 同时验证访问权限和访客会话；先审计后调用模型 |

升级仅新增`pig_chat_logins`表和`pig_guests.user_id`可空列；旧访客记录初始未绑定。原会话、消息、审计、家庭资料、组件、模型凭据和订阅不覆盖。聊天页面兼容iOS13语法。

## 专项验证

`tests/pig-chat-access.test.js`覆盖真实路由入口、来源IP/Host组合、映射IPv6、公网/其他私网/回环、伪造代理头、旧访客Cookie绕过、正确/错误登录、账号审计、后台权限隔离、退出、到期、修改密码、账号切换、并发会话绑定、跨站与非JSON拒绝、HTTPS代理Cookie及防暴力尝试。

旧聊天/上下文单元测试通过独立的LAN身份夹具继续验证匿名家庭聊天，访问控制专项使用实际身份校验逻辑。Chrome端到端测试经过登录后验证聊天、刷新历史、双浏览器隔离和系统操作；WebKit测试错误密码、登录、聊天审计及退出后API恢复401。浏览器测试均使用隔离数据库与测试账号，不修改生产账号密码。

本轮验证结果：36个测试套件、511项用例通过；Chrome和WebKit端到端回归、iOS13语法检查、管理后台构建通过。
