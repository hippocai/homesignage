# 猪猪上下文专项测试与证据

执行日期：2026-11-08，时区 Asia/Shanghai。

## 结论及修复

原版本并非三类信息都完整可用：

1. 普通聊天已经携带保存的完整家庭记忆，但“查看我的基础信息”会误入自建信息列表查询，绕过模型并返回无记录。已修正这个分流。
2. 聊天模型原来没有天气字段。后台降温提醒虽然能读取预报，聊天接口没有共享这些数据。已增加天气上下文，复用天气组件的提供商和缓存，并读取降温城市当天、昨天的最高温预报。
3. 新闻原来只有最近12条，且 `tools=true` 时全部移除；“我今天出门需要注意什么？”也可能触发这一开关。已保留这些问法下的新闻，扩至最多60条，优先已判定影响家庭的事件，并明确告诉模型是否截断。

家庭记忆是长期保存的 `pig_household.profile.memory`。天气、新闻是每轮重新整理的临时上下文，不会把易过期的信息永久写进 memory。查询自建提醒或信息列表由数据库直接回答，不需要调用模型。

## 如何证明，不只看界面

自动化测试在 `providers.jsonCompletion` 边界截取实际 messages，解析第二条消息中的 JSON，逐字段断言。

真实模型测试读取线上数据库的一致性备份，再创建一次性副本。该副本保留真实家庭记忆、城市、天气供应商及资讯，调用现有 GLM `glm-5.3-flash`。测试同时验证：

- 传给模型的全文与保存值逐字相等，而不只是包含某个关键词。
- GLM 实际答复能够引用保存的记忆原文、天气数值和时间、资讯编号及标题来源。
- 每次回答均未提出新增/删除计划或系统记录；测试后记忆和计划保持原样。
- 原始家庭资料、模型完整输入和答复均不写入报告；报告保留指纹、天气、资讯编号、覆盖数量和断言结果，不含密钥。

## 详细用例

| 编号 | 前置与输入 | 核对标准 |
|---|---|---|
| C01 | 管理员HTTP接口；保存多行Markdown及自定义约定 | 实际模型输入完整保留记忆及家庭时区 |
| C02 | 新访客Cookie；同一份共享资料 | 访客聊天也携带共享记忆；不依赖管理员历史 |
| C03 | “查看我的基础信息” | 调用模型、传入家庭记忆；不误查信息列表 |
| C04 | 修改记忆、聊天、清空记忆、再聊天 | 下一轮立即使用新值或空值，不回填旧结构化资料 |
| C05 | 已绑定天气及猪猪组件，有今日和昨日预报 | 传入当前观测、来源、获取时间、两个预报及温差；最高温预报不当作实时温度；剔除无关私密字段 |
| C06 | 天气请求失败且当天无预报 | 显式unavailable；昨天数据不能冒充今天；错误内的地址及密钥不传模型 |
| C07 | 天气服务返回过期缓存 | 标记stale，并保留原获取时间；提示不可当作当前观测 |
| C08 | 无任何已配置城市 | unconfigured，不默认北京，也不从家庭自由文本猜测城市 |
| C09 | 两屏共享同一场景，另有未绑定草稿 | 同城只获取一次，只读取已启用绑定场景的城市 |
| C10 | 16条有效新闻/热搜，另有过期、撤下、未来事件 | 16条全部传入，较早的通勤事件仍在；三个无效事件排除；来源、报道时间和摘要保留 |
| C11 | “我今天出门需要注意什么？” | 即便tools开关打开，也包含天气和新闻；空动作不写系统记录 |
| C12 | 65条有效资讯 | 最多60条；coverage准确报告65/60及truncated=true |
| C13 | 后台生活影响判断 | 实际判断请求包含完整家庭资料及新闻正文摘要 |
| C14 | 已确认影响家庭的旧新闻，后又新增60条资讯 | 关联旧新闻优先，不被更新但无已知关联的条目挤出 |
| C15 | 天气请求不返回 | 最多等待2.5秒后继续聊天，天气标记缺失，记忆和新闻仍在 |

首轮13项中9项失败，复现了上述分流、缺失与截断问题；修复后增加优先级和超时边界测试，专项15项全部通过。

最终全量回归：29个测试套件、419个用例全部通过；真实GLM上下文验收4/4通过。接口文档已同步说明两种聊天入口的上下文范围、天气超时降级及资讯截断规则。

## 执行方法

确定性测试使用内存数据库及天气/模型替身，不依赖真实外部服务：

```powershell
node node_modules/jest/bin/jest.js --runInBand --forceExit --runTestsByPath tests/pig-context.test.js
```

真实验收必须提供SQLite一致性备份，并在环境中提供已配置供应商的凭据（也可沿用备份中的凭据表）。不得将在线WAL数据库直接当作文件复制：

```powershell
$env:PIG_CONTEXT_SNAPSHOT = 'C:\path\consistent-backup.db'
$env:PIG_CONTEXT_REPORT = 'C:\path\context-evidence.json'
node tests/browser/pig-context-live.js
```

脚本会创建一次性副本并设为唯一数据库路径，结束后删除该副本。真实天气请求、真实模型调用可能消耗供应商额度；不会启动真实屏幕的推送服务，也不会在生产数据库写测试聊天、计划、提醒或资讯。

## 边界

- 家庭自由文本的变化按下一轮聊天生效；新闻和天气中的文本不是操作授权。
- 天气观测最多4个城市，降温预报最多4个城市；只读取已启用场景绑定的配置，不静默推断家庭地址。天气源慢、失败、未配置时会如实说明缺失。
- 当前接入的是天气组件的当前观测，以及已有降温模块保存的最高温预报；没有额外接入明天逐小时预报。模型不得自行推测明天的具体温度。
- 新闻仍遵守兴趣/不感兴趣、发布状态与有效期。超过60条时优先已判定的家庭影响，其余按更新时间；上下文明确标记截断。没有命中具体生活风险时应说明依据不足。
- 本次证据证明数据确实进入真实模型请求，且模型在本轮验收能使用这些数据；不保证所有自然语言问法或供应商未来输出永远正确。更换模型或上下文逻辑后应重跑。
